# Drift Migration Guide

This document explains the migration from sqflite to Drift for cross-platform offline support, including web.

## Why Drift?

- **Cross-platform**: Works on Android, iOS, Windows, macOS, Linux, and **Web**
- **Type-safe**: Generated code with compile-time checks
- **Better performance**: Optimized queries and batch operations
- **Web support**: Uses SQLite WASM for web platform
- **Modern API**: Reactive streams and async/await support

## Architecture

### Database Structure

The database is defined in `lib/database/`:

- `tables.dart` - Table definitions (Files, CachedPdfs, Annotations, SyncQueue)
- `database.dart` - Main database class with queries
- `database.g.dart` - Generated code (auto-generated by build_runner)
- `drift_worker.dart` - Web worker for non-blocking database operations on web

### Tables

1. **Files** - File/folder metadata from Google Drive
2. **CachedPdfs** - Actual PDF file bytes for offline access
3. **Annotations** - PDF annotations (highlights, comments, etc.)
4. **SyncQueue** - Offline operations queue for sync when online

## Web Support

Drift uses SQLite WASM to run on web browsers:

### Required Files

- `web/sqlite3.wasm` - SQLite compiled to WebAssembly
- `web/sqlite3.wasm.js` - JavaScript loader for WASM
- `web/drift_worker.js` - Web worker script (optional, for better performance)

### Setup for Web

1. The `sqlite3_web` package is included in dependencies
2. The WASM files are loaded automatically by the package
3. The database runs in a web worker to avoid blocking the UI

## Usage

### Initialize Database

The database is initialized automatically when `CacheService` is created:

```dart
final cacheService = CacheService();
```

### Cache File Metadata

```dart
await cacheService.cacheFileMetadata(driveFile);
```

### Get Cached Files

```dart
final files = await cacheService.getCachedFiles(parentId);
```

### Cache PDF Bytes

```dart
await cacheService.cachePdfBytes(fileId, pdfBytes);
```

### Get Cached PDF

```dart
final pdfBytes = await cacheService.getCachedPdf(fileId);
```

### Cache Annotations

```dart
await cacheService.cacheAnnotation({
  'id': 'annotation-id',
  'file_id': 'file-id',
  'page_number': 1,
  'annotation_type': 'highlight',
  'content': 'Selected text',
  'position': {'x': 100, 'y': 200},
  'color': '#FFFF00',
  'created_at': DateTime.now(),
  'modified_at': DateTime.now(),
});
```

## Development

### Generate Code

After modifying table definitions in `tables.dart`, run:

```bash
dart run build_runner build --delete-conflicting-outputs
```

Or for continuous generation during development:

```bash
dart run build_runner watch --delete-conflicting-outputs
```

### Add New Table

1. Create table class in `tables.dart`:

```dart
class MyNewTable extends Table {
  TextColumn get id => text()();
  TextColumn get name => text()();
  
  @override
  Set<Column> get primaryKey => {id};
}
```

2. Add to database in `database.dart`:

```dart
@DriftDatabase(tables: [
  Files,
  CachedPdfs,
  Annotations,
  SyncQueue,
  MyNewTable, // Add here
])
```

3. Run build_runner to generate code

4. Add query methods in `AppDatabase` class

## Migration from sqflite

The migration is complete. Key changes:

1. **Import changes**: `sqflite` → `drift`
2. **Database class**: Custom class → `AppDatabase extends _$AppDatabase`
3. **Queries**: Raw SQL → Type-safe Dart methods
4. **Inserts**: Maps → Companion objects
5. **Web support**: Not available → Fully supported

## Performance Tips

1. **Batch operations**: Use `insertFiles()` instead of multiple `insertFile()` calls
2. **Indexes**: Already created on foreign keys and frequently queried columns
3. **Transactions**: Drift automatically uses transactions for batch operations
4. **Web workers**: Database operations run in a separate thread on web

## Troubleshooting

### Web: "Failed to load sqlite3.wasm"

Make sure the WASM files are in the `web/` directory. Run:

```bash
flutter pub get
```

The `sqlite3_web` package should handle this automatically.

### Build errors after schema changes

Run:

```bash
dart run build_runner clean
dart run build_runner build --delete-conflicting-outputs
```

### Type errors in generated code

Make sure your table definitions are correct and run build_runner again.
