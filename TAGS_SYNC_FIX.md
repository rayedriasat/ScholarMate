# Tags Sync to Supabase - Fix

## Problem

Tags were working locally on Android but not syncing to Supabase. The backend was returning 422 validation errors:

```
'msg': 'Input should be a valid UUID, invalid length: expected length 32 for simple format, found 21'
'input': '111828646872592591995'
```

## Root Cause

**User ID Type Mismatch:**
- Frontend sends Google sub claim (string like `111828646872592591995`)
- Backend expected UUID format
- Database schema defined `user_id` as `UUID` type

The system has two types of user IDs:
1. **Google sub claim** - String from Google OAuth (what the frontend uses)
2. **Database UUID** - Generated by Supabase (not being used for tags)

## Solution

Changed the entire tags system to use Google sub claims (strings) instead of UUIDs for `user_id`:

### 1. Backend API (`backend/app/routers/tags.py`)
- Changed all `user_id` parameters from `UUID` to `str`
- Updated descriptions to clarify it's a Google sub claim

### 2. Backend Service (`backend/app/services/tag_service.py`)
- Updated all method signatures to accept `str` for `user_id`
- Service already converted to string when querying Supabase

### 3. Backend Models (`backend/app/models/tag.py`)
- Changed `TagResponse.user_id` from `UUID` to `str`
- Changed `FileTagResponse.user_id` from `UUID` to `str`

### 4. Database Schema
- **New migration**: `005_fix_tags_user_id.sql`
- Changes `user_id` from `UUID` to `VARCHAR(255)` in both tables
- Temporarily uses permissive RLS policies (since not using Supabase auth)

### 5. Original Migration Updated (`004_tags.sql`)
- Updated to use `VARCHAR(255)` for `user_id` (for fresh installs)
- Commented out Supabase auth-based RLS policies

## How to Apply

### Step 1: Run the Migration on Supabase

```sql
-- Run this in your Supabase SQL Editor:
-- backend/supabase_migrations/005_fix_tags_user_id.sql
```

Or copy-paste the migration content directly.

### Step 2: Restart the Backend

```bash
cd backend
uv run python run.py
```

### Step 3: Test on Android

The app should now sync tags to Supabase. Check the backend logs - you should see:
- ✅ `200` responses instead of `422`
- ✅ "Created tag..." log messages
- ✅ "Added tag to file..." log messages
